# Simple Command: Core

> 本项目的绝大部分代码由 **Deepseek Harness** 完成。

## 这是什么

Simple Command: Core（下称 **SC Core**）是 Simple Command 全家桶的**唯一前置模组**与**共享基础设施**。

Simple Command 是一套围绕 `/sc` 指令命名空间构建的 Minecraft 模组全家桶，目标是把服务器运维、玩家传送、物品管理、日志系统统一到一套指令体系下，并用 **CSC 语言**作为跨子模组的表达式与脚本层。

SC Core 不实现任何具体业务指令。它只提供子模组共用的能力，让 Item、Server 等子模组保持“薄壳”，把精力放在各自的业务逻辑上。

判断标准：往 Core 加东西前问三个问题——至少两个子模组会用吗？和具体业务无关吗？它是“能力”还是“内容”？三个都通过才进 Core。

## 它提供什么

- **命名空间与指令分发**：`/sc <命名空间> <子指令...>` 的统一入口。子模组以声明的方式注册自己的命名空间、指令树与短名，不自己抢根指令。
- **短名机制**：子模组可把某个子指令挂成根级别名（`sc server backup` → `backup`）。粒度是**子指令路径**而不是整个命名空间，是否启用由该命名空间的配置开关决定；同名冲突静默跳过并记警告，回落到完整路径。
- **配置托管**：每个命名空间一份 `config/sc/<命名空间>.toml`，支持开关短名、重载与保存。改动默认只作用于内存，显式保存才落盘；文件缺失或损坏时退回默认值。
- **执行上下文抽象**：把“谁在执行、参数是什么、怎么回话”抽成与具体指令框架无关的契约，让同一套效果逻辑能在 Forge、将来的 Paper 等不同平台上复用。
- **CSC 宿主**：给 CSC 提供变量表、聊天/日志输出、日志流与文件流，并把诊断按级别投递。文件流被限制在固定目录内，越界路径直接拒绝。
- **类型化变量**：变量有声明类型（`int` / `float` / `string` / `bool` / `list`），值以 `CscValue` 存储，类型信息写进世界存档、读回来不丢。变量表不分玩家，跨世界不共享。
- **玩家数据存储**：按玩家持久化的跨世界数据（home 坐标这类），跨维度可用、死亡不丢。
- **文件路径管理**：统一解析世界目录下的备份、日志路径，配置目录下的脚本、文件流路径，以及跨存档共享的缓存目录。
- **错误与日志分级**：严重错误三级投递（聊天栏 + 游戏日志 + 指令日志），隐式转换只进指令日志；出错片段原样保留，其余照常输出。

## 玩家会用到的指令

CSC 的全部指令都在 `csc` 命名空间下：

```
/sc csc <语句...>              直接执行一条或多条 CSC 语句
/sc csc run <脚本名>           执行 config/sc/scripts/<脚本名>.csc
/sc csc repl                   进入聊天栏 REPL，sys exit 退出
```

语句关键字与脚本一致：`var` / `list` / `ctrl` / `io` / `log` / `file` / `sys`。
指令里不写分号也可以；块语句（`ctrl if` 等）写不进指令，请用脚本或 REPL。

每个命名空间还自带三条管理指令：

```
/sc <命名空间> shortcommand [true|false]   短名开关（只改内存）
/sc <命名空间> saveconfig                  把内存中的配置写回磁盘
/sc <命名空间> reloadconfig                从磁盘重新读取配置
```

`csc` 命名空间与命名空间管理指令需要 OP 权限；子模组自己的子指令默认不限权限。

## 配置与数据

配置按命名空间分文件，放在 `config/sc/` 下，文件名就是命名空间名。文件里既有 Core 的通用键
（如短名开关），也有子模组自己的业务键。

| 内容 | 位置 |
| --- | --- |
| 变量 | 世界级存档数据，挂在主世界，跨世界不共享 |
| 玩家数据 | 世界级存档数据，按玩家索引 |
| 备份 | `<世界目录>/sc_backups/` |
| 指令日志 | `<世界目录>/sc_logs/command.log`，按大小滚动并保留历史文件 |
| CSC 日志流 | `<世界目录>/sc_logs/` |
| CSC 文件流 | `<配置目录>/sc/csc/files/` |
| CSC 脚本 | `<配置目录>/sc/scripts/` |
| 短名表缓存 | `~/.sc/mapping/`，跨存档共享 |

## 设计原则

1. **Core 薄且通用**：只提供“至少两个子模组会用、且与具体业务无关”的能力。业务逻辑（备份打包、传送队列、物品格式）全部留给子模组。
2. **子模组是薄壳**：入口类只做注册，指令树与效果类调用 Core 能力，不重复实现 Core 已有的东西。
3. **Core 是唯一前置**：子模组只声明对 Core 的强制依赖，不直接依赖 CSC 或其他子模组。
4. **CSC 内嵌在 Core 里**：CSC 以 Maven 坐标引入并在打包时嵌入 Core 的 jar，避免多个子模组各带一份导致版本分裂。
5. **内核与平台适配分层**：核心逻辑不绑定加载器 API，各平台适配层只负责把内核接到该平台的指令注册事件上。
6. **语言规范先于实现**：CSC 的语义变更需要版本号与规范文档记录，破坏性变更慎重。

## 它不做什么

- 具体业务：备份打包、传送队列、home 坐标校验、物品字符串格式。
- 原版变量映射（先保留命名空间，不实现）。
- CSC 的语言实现本身（那是 `Simple Command CSC` 的事，Core 只做宿主与封装）。
- GUI、客户端渲染、网络包。

## 兼容性

- **首要目标**：Forge 1.20.1。主版本锁定 1.20.1，跨版本差异收敛到适配层。
- **核心矩阵**：Fabric / NeoForge / Quilt（复用 Fabric）、Paper 系（独立适配层）。
- **安装形态**：双端模组，指令逻辑在服务端执行。

## 当前状态

已完成：命名空间注册与分发、短名、配置托管、执行上下文、CSC 宿主（含日志流/文件流/
诊断分级）、类型化变量、玩家数据、路径管理，以及内置的 `csc` 命名空间与聊天 REPL。

尚未开始：SC Server（backup / tpa / home / serverlog）、SC Item（物品字符串与 give 系列）、
原版变量映射、Paper 适配层、CSC 的模块系统与完整沙箱。

## 命名与构建

| 项目 | 值 |
| --- | --- |
| 目录 | `Simple Command Core` |
| Gradle 工程 | `simple-command-core` |
| modId | `sc_core` |
| Maven 坐标 | `cd.cc.currkill:sc_core:0.2.0` |
| 版本 | `0.2.0` |

Core 通过 Maven 坐标依赖 CSC，**不再把 CSC 当作 Gradle 子构建**，所以构建顺序是
「先 CSC，后 Core」。
